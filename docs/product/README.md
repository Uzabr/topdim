## MVP границы

В текущем MVP приоритет такой:

1. Купонный контур: каталог, детальная страница, варианты купона, покупка.
2. Merchant/partner контур: onboarding, профиль мерчанта, заявки на купоны, согласование.
3. Purchased coupon lifecycle: купленный купон, PIN/QR, погашение, история.
4. Buyer continuity: профиль, заказы, возвраты, жалобы, отзывы и уведомления.
5. Admin/moderation: управление мерчантами, купонами, статусами и безопасными переходами.
6. Bazaar/directory: не основной приоритет до стабилизации купонного и партнёрского флоу.

## Бизнес-инварианты

- На момент публикации купона мерчант уже должен существовать со всеми обязательными данными.
- ACTIVE купон нельзя свободно редактировать или удалять, чтобы не ломать уже купленные купоны.
- Покупка должна повторно проверять статус купона, статус варианта, лимиты и срок покупки.
- Погашение возможно только для правильного мерчанта и только один раз.
- Кассир не выбирает филиал вручную: филиал должен приходить из его access context.
- Админ может снимать купон с продажи, но не должен вручную гасить купоны вместо мерчанта без отдельного support-flow.

## Когда обновлять этот раздел

Обновляй product-документацию, если меняются:

- статусы купона, заявки, заказа или purchased coupon;
- права ролей `USER`, `PARTNER`, `MODERATOR`, `ADMIN`, `SUPER_ADMIN`;
- партнёрский onboarding;
- покупка или погашение купона;
- правила публикации, архивации или скрытия купона.

Важно: отдельной JWT-роли `PARTNER_CASHIER` сейчас нет. Кассир хранится как staff с `role=CASHIER`, а его login-user имеет роль `PARTNER`; доступ ограничивается через partner access context.
