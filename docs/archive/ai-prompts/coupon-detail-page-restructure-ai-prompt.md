# Coupon Detail Page Restructure AI Prompt

```text
Используй superpowers и все локальные инструкции проекта.

Перед началом работы обязательно:
1. Прочитай AGENTS.md в корне проекта.
2. Найди локальные скилы:
   - rg --files frontend -g 'SKILL.md'
   - rg --files services -g 'SKILL.md'
   - rg --files -g 'SKILL.md'
3. Если в папках frontend или services есть SKILL.md, обязательно прочитай и используй релевантные скилы перед изменением файлов в этих папках.
4. Если используешь superpowers, начни с подходящих скилов:
   - superpowers:brainstorming для уточнения структуры;
   - superpowers:test-driven-development, если меняешь бизнес-логику или поведение;
   - superpowers:systematic-debugging при ошибках;
   - superpowers:verification-before-completion перед финальным отчётом.

Работай как senior frontend engineer: сначала изучи текущую реализацию страницы купона, потом реализуй без редизайна.

Задача:
Доработать страницу детального просмотра купона TopDim по структуре, похожей на Chocolife, но НЕ копировать дизайн, цвета, шрифты, header, поиск, город, категории или визуальный стиль Chocolife.

Файл старта:
frontend/web-app/src/pages/CouponDetailPage.tsx

Также изучи связанные файлы и компоненты:
- frontend/web-app/src/pages/CouponDetailPage.css
- frontend/web-app/src/api/coupons.ts
- frontend/web-app/src/api/reviews.ts
- frontend/web-app/src/components/ui/ImageSlider.tsx
- frontend/web-app/src/components/ui/Tabs.tsx
- frontend/web-app/src/components/ui/StarRating.tsx
- frontend/web-app/src/components/ui/ShareButton.tsx
- frontend/web-app/src/store/cartStore.ts
- frontend/web-app/src/store/favoritesStore.ts

Важно:
Не менять текущий дизайн проекта.
Не менять цвета, шрифты, кнопки, карточки, общий стиль и дизайн-систему TopDim.
Не делать редизайн.
Не копировать визуальный стиль Chocolife.
Не добавлять верхний header, город, поиск, категории и прочую верхнюю навигацию.
Нужно реализовать только структуру контентной части страницы купона.

Что сделать:

1. Перестроить контентную часть страницы купона.

2. Вверху сделать Coupon Hero:
   - слева галерея изображений;
   - справа название купона;
   - название партнера / мерчанта;
   - бейдж скидки;
   - цена “от”;
   - адрес / локация;
   - срок, до которого можно купить купон;
   - срок, до которого можно использовать купон;
   - главная кнопка “Выбрать сертификат”;
   - статистика: сколько купили, рейтинг, количество отзывов, если эти данные реально есть.

3. Под hero сделать вкладки / панель действий:
   - Информация;
   - Отзывы;
   - Вопросы, только если есть реальные данные, иначе не показывать или сделать disabled;
   - В избранное;
   - Поделиться.

4. Ниже сделать основную сетку:
   - левая колонка: варианты сертификатов + важная информация;
   - правая колонка: “О партнере”.

5. Варианты купонов брать из `coupon.options`.
   Если `options` нет, использовать существующий fallback из текущей страницы.

6. Кнопки “Купить” и “В корзину” должны использовать текущую cart/purchase логику.

7. Кнопка “Выбрать сертификат” должна скроллить к блоку вариантов.

8. “В избранное” использовать существующий `favoritesStore`.

9. “Поделиться” использовать существующий `ShareButton`, Web Share API или copy link, если это уже реализовано.

10. Блок “Важная информация” собрать только из реальных данных TopDim:
   - адрес;
   - срок покупки;
   - срок использования;
   - QR/PIN использование;
   - базовые условия использования купона.

11. Не использовать MOCK_REVIEWS и фейковые отзывы.
   Если есть `reviewsApi`, подключи реальные отзывы.
   Если отзывов нет, покажи empty state.

12. Разбей страницу на компоненты:
   - CouponHeroSection
   - CouponImageGallery
   - CouponSummaryPanel
   - CouponPageTabs
   - CouponInfoLayout
   - CouponVariantsSection
   - CouponVariantCard
   - CouponImportantInfoSection
   - MerchantInfoSection

13. Сохрани текущую дизайн-систему TopDim:
   - текущие цвета;
   - текущие кнопки;
   - текущие карточки;
   - текущие отступы;
   - текущий общий стиль.

14. Сделай адаптив:
   - desktop: hero в две колонки, контент ниже в две колонки;
   - mobile: одна колонка;
   - на mobile сначала галерея, потом summary, потом варианты, важная информация, партнер;
   - вкладки должны быть горизонтально scroll.

Запреты:
- не делать редизайн;
- не копировать Chocolife;
- не добавлять header/город/поиск/категории сверху;
- не добавлять фейковые отзывы;
- не добавлять фейковые вопросы;
- не добавлять фейковые метрики;
- не менять бизнес-логику покупки;
- не ломать текущие routes;
- не удалять существующую cart/favorites/share логику.

Проверки:
1. Запусти:
   cd frontend/web-app
   npm run build

2. Вручную проверь страницу купона на desktop/mobile.

3. Проверь действия:
   - “Выбрать сертификат” скроллит к вариантам;
   - “Купить” работает как раньше;
   - “В корзину” работает как раньше;
   - “В избранное” работает как раньше;
   - “Поделиться” работает как раньше;
   - отзывы не показывают фейковые данные.

Финальный отчёт:
- какие компоненты созданы;
- какие файлы изменены;
- что проверено;
- какие данные пока скрываются из-за отсутствия API.
```
