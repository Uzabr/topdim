# Карта ролей и пользовательских путей

## Роли продукта

| Понятное название | Технический контекст | Главная цель |
|---|---|---|
| Гость | без JWT / `GUEST` session | Изучить предложения и начать регистрацию |
| Покупатель | `USER` | Купить, использовать купон и получить поддержку |
| Владелец партнёра | `PARTNER`, owner context | Управлять предложениями, командой и результатом |
| Кассир | `PARTNER`, staff `CASHIER` | Быстро и безопасно погасить купон |
| Модератор | `MODERATOR` | Подготовить контент и обработать обращения |
| Администратор | `ADMIN` | Управлять операционными процессами |
| Суперадминистратор | `SUPER_ADMIN` | Управлять доступами, ролями и аудитом |
| Telegram-пользователь | зависит от сценария | Войти или пройти concierge/approval flow |

Кассир — не отдельная глобальная JWT-роль. Его ограничения определяются
принадлежностью к мерчанту и локации.

## Сквозной жизненный цикл

```text
Партнёрская заявка
→ создание/связывание мерчанта
→ заявка на предложение
→ подготовка модератором
→ согласование партнёром
→ публикация
→ поиск покупателем
→ заказ и demo-оплата
→ выпуск купона
→ погашение кассиром
→ статистика / отзыв / поддержка / возврат
```

## Разделение ответственности

- партнёр отвечает за правдивость условий и их исполнение;
- модератор отвечает за подготовку и корректный статус контента;
- покупатель отвечает за соблюдение условий использования;
- кассир погашает только купон своего merchant/location context;
- администратор принимает операционные решения в пределах полномочий;
- суперадминистратор контролирует привилегированные доступы;
- система хранит состояния, проверяет основные ограничения и журналирует
  критичные административные действия.
