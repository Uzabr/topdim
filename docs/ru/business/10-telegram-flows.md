# Telegram-сценарии

Telegram в sizbiz используется в двух разных контекстах. Их нельзя смешивать.

## 1. Telegram Login покупателя

1. Пользователь выбирает вход через Telegram.
2. Telegram возвращает подписанные данные.
3. Backend проверяет подпись и срок данных.
4. Система находит либо создаёт связанный пользовательский аккаунт согласно
   поддерживаемому flow.
5. Пользователь получает обычную авторизованную сессию sizbiz.

Telegram Login не означает, что бот получает доступ к паролю или всем данным
пользователя.

## 2. Concierge bot для партнёра

1. Представитель бизнеса начинает диалог.
2. Бот по шагам собирает данные заявки или идеи акции.
3. Внутренний bot endpoint создаёт lead.
4. Команда sizbiz обрабатывает lead в административном процессе.
5. Подготовленное предложение отправляется на согласование.
6. Партнёр одобряет либо запрашивает исправления через поддерживаемое действие.

Внутренние bot endpoints защищаются отдельным API key, а не пользовательским
JWT. Ключ нельзя передавать в сообщения или публичную документацию.

## 3. Уведомления

События продукта могут создавать in-app уведомления и инициировать
email/SMS-каналы. Реальная Telegram/email/SMS-доставка зависит от настроенного
провайдера и не должна обещаться как безусловная.

## Сбои и безопасное поведение

- неверная Telegram-подпись → отказ во входе;
- устаревшие данные → отказ;
- неверный bot API key → отказ без создания lead;
- незавершённый диалог → данные не считаются согласованным предложением;
- повторная команда approve/revision не должна ломать state machine;
- недоступность бота не отменяет ownership и статусные проверки backend.
